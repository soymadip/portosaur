title: "Editor Support"
desc: "Suggestions, hover help, and error checking in porto.yml and MDX pages, right in your editor."
icon: "md:code"
---

Portosaur ships a small language server, `porto-lsp`, that understands your MDX pages. In frontmatter it suggests keys and values, explains each key on hover, and flags unknown keys and wrong types. In the page body it suggests components like `<Btn>` and `<Hint>` while you type, with their props.

`porto.yml` is not handled by the server. Every `porto.yml` carries a `$schema` line at the top, and the YAML support in your editor reads it to suggest config keys and values, explain each key on hover, and flag mistakes.

The server only activates inside a Portosaur project, so it stays quiet in other folders.

---

## VS Code

Install the [Portosaur extension](https://marketplace.visualstudio.com/items?itemName=soymadip.portosaur) from the Marketplace (also on [Open VSX](https://open-vsx.org/extension/soymadip/portosaur)). You also need the [MDX extension](https://marketplace.visualstudio.com/items?itemName=unifiedjs.vscode-mdx), which provides the MDX language itself, and the [YAML extension](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml), which handles `porto.yml` through the `$schema` line. Both are installed automatically along with the Portosaur extension.

On first use the extension downloads the matching server binary from the Portosaur releases and checks it before running it. There is nothing else to set up.

Two settings are available:

| Setting                  | What it does                                                                                                   |
| :----------------------- | :------------------------------------------------------------------------------------------------------------- |
| `portosaur.server.path`  | Use a local build of the server instead of the downloaded one.                                                 |
| `portosaur.trace.server` | Log the traffic between the editor and the server (`off`, `messages`, `verbose`). Useful when reporting a bug. |

If the server stops responding, run **Portosaur: Restart Language Server** from the Command Palette.

### Preview

Open an MDX page and run **Portosaur: Preview Page** from the Command Palette, or press the preview button in the editor toolbar. The extension starts the dev server for the project if it is not running yet, then shows the page beside the editor. The panel follows the file you are editing, so switching to another page moves the preview to it.

If a server is already answering on the preview port, the extension reuses it instead of starting its own. Stop a server the extension started with **Portosaur: Stop Preview Server**. The port is `portosaur.preview.port` (3000 by default).

## Zed

Install `portosaur` from the extension list, along with the [MDX extension](https://zed.dev/extensions/mdx), which provides the MDX language itself. The server binary is downloaded on first use, the same as in VS Code. `porto.yml` works through Zed's built-in YAML support, which reads the `$schema` line, with nothing extra to install.

To use a local build of the server instead, set the binary path in your Zed settings:

```json
{
  "lsp": {
    "porto-lsp": {
      "binary": {
        "path": "/path/to/porto-lsp"
      }
    }
  }
}
```

## Other editors

Neovim, Helix, and anything else that speaks the Language Server Protocol can run the server directly. Download the binary for your platform from the [Portosaur releases](https://github.com/soymadip/portosaur/releases) and start it with the `--stdio` flag. For `porto.yml`, point your YAML language server at the schema with the `$schema` line at the top of the file.
