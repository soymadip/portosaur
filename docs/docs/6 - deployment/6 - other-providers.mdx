Portosaur builds a static site into `build/`, so the output can be hosted by any static provider.

Portosaur generates a Netlify configuration file, Vercel and Cloudflare Pages are configured in their dashboards rather than through CI.

For all providers below, configure the site URL in `config.yml` if the build environment does not provide a Pages URL automatically:

```yaml
site:
  url: "https://www.example.com"
  base_url: "/"
```

Use the provider's actual preview or production URL.  
If the site is hosted under a path prefix, set `base_url` to that path, including the leading and trailing slashes.

## 1. Vercel

Configure Vercel to run the Portosaur build:

1. Import the repository in the [Vercel Dashboard](https://vercel.com).
2. Set **Framework Preset** to **Other**.
3. Set the build command to `bun run build` and the output directory to `build`.
4. Ensure the build environment uses the Bun version from the project's `packageManager` field, or set `BUN_VERSION` to `1.3.12`.
5. Set the production branch, then deploy and review the build log.

Set `site.url` and `site.base_url` to the Vercel production URL and `/`, or configure a custom domain in Vercel and use that domain in `site.url`.

## 2. Cloudflare Pages

Configure the Pages project in Cloudflare:

1. Open **Workers & Pages → Create application → Pages → Connect to Git** and select the repository.
2. Choose **None** as the framework preset so Cloudflare uses the commands you provide.
3. Set the build command to `bun run build` and the output directory to `build`.
4. Select the production branch and ensure the build environment has Bun `1.3.12` available (for example, through `BUN_VERSION`).
5. Save the settings, push a commit, then check the deployment logs and assigned Pages URL.

Set `site.url` to the assigned Cloudflare Pages URL or your custom domain, and set `site.base_url` to `/` unless hosting under a path prefix.
