Portosaur styles sites with **Tailwind CSS v4** plus a **token theming system**. Layout and spacing use Tailwind utilities; every color, font, radius, and shadow comes from a `--porto-*` CSS variable, so recoloring a site means overriding variables — never rewriting component CSS.

The old Infima (`--ifm-*`) variables are gone. If you have custom CSS from Portosaur 0.x, see the [migration table](#ifm--porto-mapping) at the bottom of this page.

---

## How theming works

Two attributes on `<html>` select the look:

- `data-scheme` — the color scheme (`portosaur`, `dracula`, …), from `theme.color_scheme`.
- `data-theme` — `light` or `dark`, from `theme.default_mode` (or the visitor's toggle choice, which is remembered).

Each bundled scheme assigns values to the same `--porto-*` tokens under `[data-scheme="<name>"][data-theme="light"]` and `[data-theme="dark"]` blocks. All six scheme files ship in the theme CSS; only the active scheme's block applies.

Load order (later files win):

1. Theme CSS (`custom.css`: Tailwind, tokens, all six schemes, overrides).
2. Your custom scheme file, if `theme.color_scheme` points at a path.
3. Your `theme.custom_css` file(s).

```yaml
theme:
  color_scheme: "portosaur"
  default_mode: "dark" # "light", "dark", or "system"
  custom_css: "src/css/custom.css"
```

## Tokens

### Color tokens (assigned per scheme, per mode)

Every scheme defines all of these. The names are stable — override them, don't rename them.

| Token                                                                                                                                | Meaning                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| `--porto-primary`, `--porto-primary-rgb`                                                                                             | Brand / link color, and its `r, g, b` triplet for `rgba()` |
| `--porto-primary-dark`, `--porto-primary-darker`, `--porto-primary-darkest`                                                          | Darker primary steps                                       |
| `--porto-primary-light`, `--porto-primary-lighter`, `--porto-primary-lightest`                                                       | Lighter primary steps                                      |
| `--porto-success`, `--porto-success-rgb`                                                                                             | Success green                                              |
| `--porto-warning`, `--porto-warning-rgb`                                                                                             | Warning amber                                              |
| `--porto-danger`, `--porto-danger-rgb`                                                                                               | Danger red                                                 |
| `--porto-info`, `--porto-info-rgb`                                                                                                   | Info blue                                                  |
| `--porto-secondary`                                                                                                                  | Muted accent (lavender / gray, per scheme)                 |
| `--porto-red`, `--porto-orange`, `--porto-yellow`, `--porto-green`, `--porto-teal`, `--porto-blue`, `--porto-purple`, `--porto-pink` | Accent palette                                             |
| `--porto-bg`                                                                                                                         | Page background                                            |
| `--porto-bg-alt`                                                                                                                     | Alternate background (footer, code blocks, overscroll)     |
| `--porto-surface-0`, `--porto-surface-0-rgb`                                                                                         | Raised surface (cards, table stripes)                      |
| `--porto-surface-1`                                                                                                                  | Higher surface                                             |
| `--porto-surface-2`, `--porto-surface-2-rgb`                                                                                         | Highest surface (hover overlays)                           |
| `--porto-text`                                                                                                                       | Body text                                                  |
| `--porto-text-muted`                                                                                                                 | Secondary / muted text                                     |
| `--porto-border`                                                                                                                     | Borders and dividers                                       |
| `--porto-code`                                                                                                                       | Inline code text                                           |
| `--porto-gray-0` … `--porto-gray-1000`                                                                                               | Grayscale, lightest to darkest in each mode                |

The `-rgb` triplets exist so you can build translucent colors: `rgba(var(--porto-primary-rgb), 0.1)`. For tokens without an `-rgb` variant, use `color-mix(in srgb, var(--porto-secondary) 15%, transparent)` instead.

### Tailwind utilities

The tokens are mapped to Tailwind utilities, so components and MDX can use either form:

```html
<!-- Utility form -->
<div class="bg-porto-surface-0 text-porto-text border-porto-border">…</div>

<!-- Arbitrary-value form (works for any token, no mapping needed) -->
<div class="bg-(--porto-surface-0)">…</div>
```

Available utilities include `bg-porto-*`, `text-porto-*`, `border-porto-*` for every color token, `font-porto-heading` / `font-porto-body` / `font-porto-markdown` / `font-porto-mono`, `rounded-porto`, and `shadow-porto-lw` / `shadow-porto-md` / `shadow-porto-lg` / `shadow-porto-tl`.

## Overriding tokens in `custom_css`

Point `theme.custom_css` at your file(s) — they load after the theme CSS, so your values win. Scope overrides by mode when they differ:

```css title="src/css/custom.css"
/* Both modes */
:root {
  --porto-radius: 0.75rem;
}

/* Light mode only */
[data-theme="light"] {
  --porto-primary: #0284c7;
  --porto-primary-rgb: 2, 132, 199;
}

/* Dark mode only */
[data-theme="dark"] {
  --porto-primary: #38bdf8;
  --porto-primary-rgb: 56, 189, 248;
}
```

Keep the `-rgb` triplet in sync with its color whenever you override a token that has one — translucent variants (`rgba(var(--porto-primary-rgb), …)`) read the triplet, not the hex.

## Creating a custom scheme

To build a full custom scheme, create a CSS file and link it in `config.yml`:

```yaml
theme:
  color_scheme: "./src/css/my-theme.css"
```

The file loads after the theme CSS. Define a raw palette in `:root`, then map it to the `--porto-*` tokens inside plain `[data-theme="light"]` and `[data-theme="dark"]` blocks — no bundled scheme block matches while a custom scheme is active, so the plain blocks win:

  --theme-red: #ef4444;
  --theme-orange: #f97316;
  --theme-yellow: #eab308;
  --theme-green: #22c55e;
  --theme-teal: #14b8a6;
  --theme-blue: #3b82f6;

  --theme-blue-rgb: 59, 130, 246;

## `--ifm-*` → `--porto-*` mapping

Portosaur 1.0 drops Infima. Every `--ifm-*` variable used by the old theme maps to a `--porto-*` token (or a literal value) as follows. Search your custom CSS for `--ifm-` and replace each occurrence.

### Colors

| Old `--ifm-*`                                                                                    | New equivalent                                                                                                |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `--ifm-color-primary`, `-rgb`, `-light`, `-lighter`, `-lightest`, `-dark`, `-darker`, `-darkest` | `--porto-primary` + same suffix                                                                               |
| `--ifm-color-primary-contrast-foreground`                                                        | `--porto-on-primary`                                                                                          |
| `--ifm-color-success`, `-rgb`                                                                    | `--porto-success`, `--porto-success-rgb`                                                                      |
| `--ifm-color-warning`, `-rgb`                                                                    | `--porto-warning`, `--porto-warning-rgb`                                                                      |
| `--ifm-color-danger`, `-rgb`                                                                     | `--porto-danger`, `--porto-danger-rgb`                                                                        |
| `--ifm-color-info`, `-rgb`                                                                       | `--porto-info`, `--porto-info-rgb`                                                                            |
| `--ifm-color-secondary`                                                                          | `--porto-secondary`                                                                                           |
| `--ifm-color-secondary-rgb`                                                                      | No triplet token — use `color-mix(in srgb, var(--porto-secondary) N%, transparent)`                           |
| `--ifm-color-success-darker`                                                                     | `color-mix(in srgb, var(--porto-success) 75%, black)`                                                         |
| `--ifm-color-warning-darkest`                                                                    | `color-mix(in srgb, var(--porto-warning) 60%, black)`                                                         |
| `--ifm-color-danger-darker`                                                                      | `color-mix(in srgb, var(--porto-danger) 75%, black)`                                                          |
| `--ifm-color-gray-0` … `--ifm-color-gray-1000`                                                   | `--porto-gray-0` … `--porto-gray-1000`                                                                        |
| `--ifm-color-emphasis-0` … `--ifm-color-emphasis-1000`                                           | `--porto-gray-0` … `--porto-gray-1000`                                                                        |
| `--ifm-color-emphasis-950`                                                                       | `--porto-gray-900` (nearest step)                                                                             |
| `--ifm-color-emphasis-200-rgb`, `--ifm-color-emphasis-900-rgb`                                   | No triplet tokens — use `color-mix(in srgb, var(--porto-gray-200) N%, transparent)` / `var(--porto-gray-900)` |
| `--ifm-color-white`                                                                              | Light mode: `var(--porto-bg)`; dark mode: `var(--porto-text)`                                                 |
| `--ifm-color-black`                                                                              | Light mode: `var(--porto-text)`; dark mode: `var(--porto-bg)`                                                 |
| `--ifm-color-scheme`                                                                             | No token — set by the `color-scheme` property per mode in `tokens.css`                                        |

> The `-darker` / `-darkest` semantic variants above were static Infima defaults in 0.x, not scheme-aware — the `color-mix` forms keep them in sync with the active scheme.
