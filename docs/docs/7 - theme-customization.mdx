Portosaur styles sites with **plain CSS** in a variable system derived from [Starlight](https://starlight.astro.build/)'s design system (MIT-licensed; see `packages/app/NOTICE.md`). Starlight's stylesheets are integrated into Portosaur's own CSS files in `packages/app/src/css/` (`variables.css`, `reset.css`, `content.css`, and the rest), with every identifier renamed from `sl-` to `porto-` — classes, IDs, cascade layers, and CSS custom properties (`--sl-color-*` → `--porto-color-*`). There is no Tailwind: components are styled with plain CSS in the renamed variable system, and recoloring a site means overriding variables — never rewriting component CSS.

---

## How theming works

Two attributes on `<html>` select the look:

- `data-scheme` — the color scheme (`starlight`, `portosaur`, `dracula`, …), from `theme.color_scheme`.
- `data-theme` — `light` or `dark`, from `theme.default_mode` (or the visitor's toggle choice, which is remembered).

Base values live in `css/variables.css`: dark-mode values on `:root`, light-mode overrides under `:root[data-theme="light"]`. Each bundled scheme file (`packages/app/src/css/themes/<name>.css`) is a short override block — `[data-scheme="<name>"][data-theme="light"]` and `[data-theme="dark"]` — assigning the color variables as literals. Scheme files are unlayered, so they beat the layered base values; all seven ship in the theme CSS and only the active scheme's block applies.

Your `theme.custom_css` file(s) load after the theme CSS, so your values win.

Load order (later files win):

1. Theme CSS (`custom.css`: fonts, the Starlight system, all seven schemes, overrides, print).
2. Your custom scheme file, if `theme.color_scheme` points at a path.
3. Your `theme.custom_css` file(s).

```yaml
theme:
  color_scheme: "portosaur"
  default_mode: "dark" # "light", "dark", or "system"
  custom_css: "src/css/custom.css"
```

## Bundled schemes

| Scheme       | Look                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| `starlight`  | Starlight's default palette — blue accent, the default when no scheme is set. |
| `portosaur`  | Default brand palette — dark green primary in light mode, neon green in dark. |
| `catppuccin` | Latte (light) / Mocha (dark) from the Catppuccin palette.                     |
| `dracula`    | Dracula palette, with a light Alucard-inspired mode.                          |
| `github`     | GitHub light / GitHub dark.                                                   |
| `gruvbox`    | Gruvbox light / dark.                                                         |
| `nord`       | Nord arctic palette.                                                          |

The six Portosaur schemes keep the same colors as before — only the file format changed (overrides of the renamed `--porto-*` variables instead of the old short `--color-*` tokens).

```yaml
theme:
  color_scheme: "dracula"
```

If `color_scheme` is omitted, sites default to `starlight` (both docs and portfolio).

## Tokens

### Color tokens (assigned per scheme, per mode)

Every scheme defines all of these. The names are stable — override them, don't rename them.

The grayscale and black/white are **semantic roles, not literal colors**: they flip between modes. `--porto-color-white` is the strongest foreground (white in dark mode, near-black in light mode); `--porto-color-black` is the page-background base (near-black in dark mode, white in light mode). `--porto-color-gray-1` is the most foreground gray, `--porto-color-gray-6` the most background; light mode adds `--porto-color-gray-7` (used for the navbar background).

| Variable                                                                                                                                        | Meaning                                                       |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `--porto-color-white`, `--porto-color-gray-1` … `--porto-color-gray-7`, `--porto-color-black`                                                   | Grayscale, most foreground to most background                 |
| `--porto-color-accent-low`, `--porto-color-accent`, `--porto-color-accent-high`                                                                 | Brand / link color (low = subtle background, high = text)     |
| `--porto-color-orange`, `--porto-color-green`, `--porto-color-blue`, `--porto-color-purple`, `--porto-color-red` (each `-low` / base / `-high`) | Hue colors for asides, cards, and accents                     |
| `--porto-hue-orange`, `--porto-hue-green`, `--porto-hue-blue`, `--porto-hue-purple`, `--porto-hue-red`                                          | Hue angles the hue colors are built from (override to retint) |
| `--porto-color-bg`                                                                                                                              | Page background                                               |
| `--porto-color-text`, `--porto-color-text-accent`, `--porto-color-text-invert`                                                                  | Body text, accent text (links), text on accent backgrounds    |
| `--porto-color-bg-nav`, `--porto-color-bg-sidebar`, `--porto-color-bg-inline-code`, `--porto-color-bg-accent`                                   | Navbar, sidebar, inline-code, and accent backgrounds          |
| `--porto-color-hairline`, `--porto-color-hairline-light`, `--porto-color-hairline-shade`                                                        | Borders and dividers                                          |

The derived variables (`--porto-color-text`, `--porto-color-bg-nav`, `--porto-color-bg-sidebar`, `--porto-color-bg-inline-code`, `--porto-color-bg-accent`, the hairlines) are computed from the base palette in `variables.css` — schemes don't override them, and neither should you unless you need to break the derivation.

There are no `-rgb` triplet tokens. Build translucent colors with `color-mix()` instead: `color-mix(in srgb, var(--porto-color-accent) 10%, transparent)`.

### Type scale

| Variable                                                                        | Meaning                                                 |
| ------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `--porto-text-2xs` … `--porto-text-6xl`                                         | Type scale, 12px to 64px                                |
| `--porto-text-h1` … `--porto-text-h5`, `--porto-text-body`, `--porto-text-code` | Heading / body / code sizes                             |
| `--porto-line-height`, `--porto-line-height-headings`                           | Base (1.75) and heading (1.2) line heights              |
| `--porto-font-system`, `--porto-font-markdown`, `--porto-font-system-mono`      | UI/body (Alata), MDX prose (Lexend Variable), monospace |

To change the typefaces, set `--porto-font` / `--porto-font-mono` — the system falls back to them before its own stacks.

### Layout & shadows

| Variable                                                                                   | Default                              | Meaning               |
| ------------------------------------------------------------------------------------------ | ------------------------------------ | --------------------- |
| `--porto-nav-height`                                                                       | `3.5rem` (`4rem` ≥ 50em)             | Navbar height         |
| `--porto-sidebar-width`                                                                    | `18.75rem`                           | Sidebar width         |
| `--porto-content-width`                                                                    | `45rem`                              | Content column width  |
| `--porto-mobile-toc-height`                                                                | `3rem` (`0` ≥ 72em)                  | Mobile TOC bar height |
| `--porto-nav-pad-x`, `--porto-nav-pad-y`, `--porto-sidebar-pad-x`, `--porto-content-pad-x` | `1rem` / `0.75rem` / `1rem` / `1rem` | Layout padding        |
| `--porto-shadow-sm`, `--porto-shadow-md`, `--porto-shadow-lg`                              | —                                    | Elevation shadows     |

**Dropped tokens:** the old short tokens (`--color-primary`, `--color-background`, `--color-surface`, `--color-foreground`, `--color-muted`, `--color-border`, `--color-gray-100`…`--color-gray-800`, `--color-secondary`, `--color-teal`, `--color-yellow`, `--color-pink`, and the semantic `--color-success` / `--color-warning` / `--color-danger` / `--color-info`) no longer exist — use the `--porto-*` names above. The old structural tokens (`--navbar-height`, `--radius-card`, `--font-body`, `--font-markdown`, `--scroll-margin-top`, `--pre-padding`, `--line-height`) are gone too; the layout values are the `--porto-*` names in the table above.

## Overriding tokens in `custom_css`

Point `theme.custom_css` at your file(s) — they load after the theme CSS, so your values win. Scope overrides by mode when they differ, and override the new `--porto-*` names:

```css title="src/css/custom.css"
/* Both modes */
:root {
  --porto-content-width: 50rem;
}

/* Light mode only */
[data-theme="light"] {
  --porto-color-accent: #0284c7;
}

/* Dark mode only */
[data-theme="dark"] {
  --porto-color-accent: #38bdf8;
}
```

For translucent variants, use `color-mix()` at the use site — `color-mix(in srgb, var(--porto-color-accent) 10%, transparent)` — rather than a triplet.

## Creating a custom scheme

To build a full custom scheme, create a CSS file and link it in `config.yml`:

```yaml
theme:
  color_scheme: "./src/css/my-theme.css"
```

The file loads after the theme CSS. Define a raw palette in `:root`, then map it to the `--porto-color-*` variables inside plain `[data-theme="light"]` and `[data-theme="dark"]` blocks — no `data-scheme` selector, because while a custom scheme is active `data-scheme` holds the path, so no bundled scheme block matches and the plain blocks win. Any variable you omit falls back to the Starlight defaults in `css/variables.css`, so a scheme only needs the variables it changes:

```css title="src/css/my-theme.css"
/* Optional palette — name your raw colors once, reference them below. */
:root {
  --my-blue: #3b82f6;
  --my-blue-dark: #2563eb;
  --my-blue-light: #60a5fa;
}

[data-theme="light"] {
  --porto-color-white: #0f172a;
  --porto-color-gray-1: #1e293b;
  --porto-color-gray-2: #334155;
  --porto-color-gray-3: #64748b;
  --porto-color-gray-6: #e2e8f0;
  --porto-color-gray-7: #f1f5f9;
  --porto-color-black: #ffffff;
  --porto-color-accent-low: var(--my-blue-light);
  --porto-color-accent: var(--my-blue);
  --porto-color-accent-high: var(--my-blue-dark);
  --porto-color-bg: #ffffff;
}

[data-theme="dark"] {
  --porto-color-white: #f8fafc;
  --porto-color-gray-1: #e2e8f0;
  --porto-color-gray-2: #cbd5e1;
  --porto-color-gray-3: #94a3b8;
  --porto-color-gray-6: #1e293b;
  --porto-color-black: #020617;
  --porto-color-accent-low: var(--my-blue-dark);
  --porto-color-accent: var(--my-blue-light);
  --porto-color-accent-high: #93c5fd;
  --porto-color-bg: #0f172a;
}
```

Start from the template shipped with the theme — `packages/app/src/css/themes/custom-scheme.template.css` — which has the full shape above.

Make sure your scheme defines `--porto-color-bg` and `--porto-color-accent` in each block: the asset generator reads those two from this file for the theme-color meta tag and the PWA manifest.

## Stable selectors

These classes are part of the theme's styling contract — custom CSS can target them safely. The old Docusaurus classes (`.navbar*`, `.theme-doc-*`, `.markdown`, `.footer*`, `.pagination-nav*`) no longer exist, and neither do the previous Portosaur layout classes (`.porto-doc-layout`, `.porto-doc-sidebar`, `.porto-markdown`, `.porto-toc__link--active`, `.portosaur-generated-index`, `.porto-navbar*`, `.porto-sidebar__*`, `.porto-footer*`, `.porto-search*`, `.porto-pagination*`, `.porto-breadcrumbs*`, `.porto-empty-state*`, `.porto-doc-card`, `.porto-doc-footer`) — those components now use Starlight's renamed classes.

| Selector                                                                                                   | Element                                                                     |
| ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `.porto-markdown-content`                                                                                  | Wrapper around rendered MDX content                                         |
| `.card-grid`, `.porto-link-card`                                                                           | Generated-index card grid and cards                                         |
| `.porto-code-frame`, `.porto-code-header`, `.porto-code-dots`, `.porto-code-lang`, `.porto-code-copy`      | Code-block frame, header, dots, language label, copy button                 |
| `.porto-aside`, `.porto-aside--note`, `.porto-aside--tip`, `.porto-aside--caution`, `.porto-aside--danger` | Asides (callouts)                                                           |
| `.admonition`, `.admonition-<type>`, `.admonition-heading`, `.admonition-content`                          | Callouts (`note`, `tip`, `info`, `success`, `warning`, `caution`, `danger`) |
| `.code-block-error-line`, `.code-block-success-line`                                                       | Magic-comment code line highlights                                          |
| `.porto-btn`                                                                                               | `<Btn>` component (unstyled hook — style it in `custom_css`)                |
| `.porto-details`                                                                                           | `<Details>` component (unstyled hook — style it in `custom_css`)            |
| `.sidebar-item-hidden`                                                                                     | Hidden sidebar item (root index)                                            |
| `.center`, `.hide-this`                                                                                    | Utility classes                                                             |

## `--ifm-*` → `--porto-*` mapping

The `--ifm-*` (Docusaurus) token names no longer exist in this theme. Their replacements are the `--porto-*` variables listed in the [Tokens](#tokens) section above — the main ones map like this:

| Old `--ifm-*` name               | Current `--porto-*` name                      |
| -------------------------------- | --------------------------------------------- |
| `--ifm-color-primary`            | `--porto-color-accent`                        |
| `--ifm-background-color`         | `--porto-color-bg`                            |
| `--ifm-font-color-base`          | `--porto-color-text`                          |
| `--ifm-font-family-base`         | `--porto-font-system`                         |
| `--ifm-font-family-monospace`    | `--porto-font-system-mono`                    |
| `--ifm-navbar-height`            | `--porto-nav-height`                          |
| `--ifm-color-emphasis-100`…`900` | `--porto-color-gray-1`…`--porto-color-gray-6` |
| `--ifm-heading-font-weight`      | (headings are `600` in the theme CSS)         |
