Portosaur styles sites with **Tailwind CSS v4** plus a **token theming system**. Layout and spacing use Tailwind utilities; every color, font, radius, and shadow comes from a short token variable defined in Tailwind `@theme` (`--color-surface`, `--font-body`, `--radius-card`, …), so recoloring a site means overriding variables — never rewriting component CSS. Each token is also a utility (`bg-surface`, `text-muted`, `border-border`), so components and MDX use the same names.

---

## How theming works

Two attributes on `<html>` select the look:

- `data-scheme` — the color scheme (`portosaur`, `dracula`, …), from `theme.color_scheme`.
- `data-theme` — `light` or `dark`, from `theme.default_mode` (or the visitor's toggle choice, which is remembered).

Tokens are defined directly in Tailwind `@theme` in `tokens.css`, with the portosaur scheme's values as the defaults. Each bundled scheme file (`packages/theme/src/css/themes/<name>.css`) is a short override block — `[data-scheme="<name>"][data-theme="light"]` and `[data-theme="dark"]` — assigning the ~34 color tokens as literal hex. All six scheme files ship in the theme CSS; only the active scheme's block applies.

The `dark:` Tailwind variant follows the toggle (`data-theme`), not the OS preference, so `dark:bg-surface-1` switches with the theme. Your `theme.custom_css` file(s) load after the theme CSS, so your values win.

Load order (later files win):

1. Theme CSS (`custom.css`: Tailwind, tokens, all six schemes, overrides).
2. Your custom scheme file, if `theme.color_scheme` points at a path.
3. Your `theme.custom_css` file(s).

```yaml
theme:
  color_scheme: "portosaur"
  default_mode: "dark" # "light", "dark", or "system"
  custom_css: "src/css/custom.css"
```

## Bundled schemes

| Scheme       | Look                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| `portosaur`  | Default brand palette — dark green primary in light mode, neon green in dark. |
| `catppuccin` | Latte (light) / Mocha (dark) from the Catppuccin palette.                     |
| `dracula`    | Dracula palette, with a light Alucard-inspired mode.                          |
| `github`     | GitHub light / GitHub dark.                                                   |
| `gruvbox`    | Gruvbox light / dark.                                                         |
| `nord`       | Nord arctic palette.                                                          |

The six schemes keep the same colors as before — only the file format changed (short override blocks of literal hex instead of palette indirection).

```yaml
theme:
  color_scheme: "dracula"
```

If `color_scheme` is omitted, docs sites default to `dracula` and portfolio sites to `nord`.

## Tokens

### Color tokens (assigned per scheme, per mode)

Every scheme defines all of these. The names are stable — override them, don't rename them.

| Token                                                                                                                                | Meaning                                                |
| ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| `--color-primary`, `--color-primary-dark`, `--color-primary-darker`, `--color-primary-light`                                         | Brand / link color and its used steps                  |
| `--color-success`, `--color-warning`, `--color-danger`, `--color-info`                                                               | Semantic colors                                        |
| `--color-secondary`                                                                                                                  | Muted accent (lavender / gray, per scheme)             |
| `--color-red`, `--color-orange`, `--color-yellow`, `--color-green`, `--color-teal`, `--color-blue`, `--color-purple`, `--color-pink` | Accent palette                                         |
| `--color-background`                                                                                                                 | Page background                                        |
| `--color-background-alt`                                                                                                             | Alternate background (footer, code blocks, overscroll) |
| `--color-surface`, `--color-surface-1`, `--color-surface-2`                                                                          | Raised surfaces (cards, table stripes, hover states)   |
| `--color-hover-overlay`                                                                                                              | Hover overlay (a per-scheme literal `rgba()`)          |
| `--color-foreground`                                                                                                                 | Body text                                              |
| `--color-muted`                                                                                                                      | Secondary / muted text                                 |
| `--color-border`                                                                                                                     | Borders and dividers                                   |
| `--color-gray-100` … `--color-gray-800`                                                                                              | Grayscale, lightest to darkest in each mode            |

There are no `-rgb` triplet tokens anymore. Build translucent colors with `color-mix()` instead: `color-mix(in srgb, var(--color-primary) 10%, transparent)`.

### Structural tokens (defined once, in `tokens.css`)

These are scheme-independent defaults. Fonts, radius, and shadows are also Tailwind theme keys, so they double as utilities (`font-body`, `rounded-card`, `shadow-md`); the structural values have no utilities — reference them with `var()` (e.g. `h-(--navbar-height)`).

| Token                 | Default                            | Meaning                        |
| --------------------- | ---------------------------------- | ------------------------------ |
| `--font-body`         | Alata                              | Body text                      |
| `--font-markdown`     | Lexend Variable                    | MDX prose                      |
| `--radius-card`       | `0.4rem`                           | Card corner radius             |
| `--shadow-sm`         | `0 1px 2px 0 rgba(0, 0, 0, 0.12)`  | Small elevation                |
| `--shadow-md`         | `0 5px 40px rgba(0, 0, 0, 0.15)`   | Medium elevation               |
| `--shadow-lg`         | `0 12px 28px 0 rgba(0, 0, 0, 0.2)` | Large elevation                |
| `--navbar-height`     | `3.75rem`                          | Navbar height                  |
| `--navbar-shadow`     | `0 1px 2px 0 rgba(0, 0, 0, 0.1)`   | Navbar shadow                  |
| `--scroll-margin-top` | `38px`                             | Anchor offset below the navbar |
| `--pre-padding`       | `1rem`                             | Code block padding             |
| `--line-height`       | `1.65`                             | Base line height               |

**Dropped tokens:** the primary scale is trimmed to the steps components actually use, so there is no `--color-primary-darkest`, `--color-primary-lighter`, or `--color-primary-lightest`; the grayscale is `gray-100`…`gray-800` only; there is no `--font-heading` or `--font-mono`; and there are no `-rgb` triplet tokens — build translucent colors with `color-mix()` instead. The old shadow tokens are replaced by `--shadow-sm` / `--shadow-md` / `--shadow-lg`.

### Tailwind utilities

The tokens are defined in `@theme`, so components and MDX can use either form:

```html
<!-- Utility form -->
<div class="bg-surface text-foreground border-border">…</div>

<!-- Arbitrary-value form (works for any token, no mapping needed) -->
<div class="bg-(--color-surface)">…</div>
```

Available utilities include `bg-*`, `text-*`, `border-*` for every color token, `font-body` / `font-markdown`, `rounded-card`, and `shadow-sm` / `shadow-md` / `shadow-lg`. The `dark:` variant follows the theme toggle, not the OS preference.

## Overriding tokens in `custom_css`

Point `theme.custom_css` at your file(s) — they load after the theme CSS, so your values win. Scope overrides by mode when they differ, and override the new short names:

```css title="src/css/custom.css"
/* Both modes */
:root {
  --radius-card: 0.75rem;
}

/* Light mode only */
[data-theme="light"] {
  --color-primary: #0284c7;
}

/* Dark mode only */
[data-theme="dark"] {
  --color-primary: #38bdf8;
}
```

For translucent variants, use `color-mix()` at the use site — `color-mix(in srgb, var(--color-primary) 10%, transparent)` — rather than a triplet.

## Creating a custom scheme

To build a full custom scheme, create a CSS file and link it in `config.yml`:

```yaml
theme:
  color_scheme: "./src/css/my-theme.css"
```

The file loads after the theme CSS. Define a raw palette in `:root`, then map it to the `--color-*` tokens inside plain `[data-theme="light"]` and `[data-theme="dark"]` blocks — no `data-scheme` selector, because while a custom scheme is active `data-scheme` holds the path, so no bundled scheme block matches and the plain blocks win. Any token you omit falls back to the portosaur defaults in `tokens.css`, so a scheme only needs the tokens it changes:

```css title="src/css/my-theme.css"
/* Optional palette — name your raw colors once, reference them below. */
:root {
  --my-blue: #3b82f6;
  --my-blue-dark: #2563eb;
  --my-blue-light: #60a5fa;
}

[data-theme="light"] {
  --color-primary: var(--my-blue);
  --color-primary-dark: var(--my-blue-dark);
  --color-primary-light: var(--my-blue-light);
  --color-background: #ffffff;
  --color-foreground: #0f172a;
  --color-muted: #64748b;
  --color-border: #e2e8f0;
  /* …any other tokens you want to change… */
}

[data-theme="dark"] {
  --color-primary: var(--my-blue-light);
  --color-background: #0f172a;
  --color-foreground: #f8fafc;
  --color-muted: #94a3b8;
  --color-border: #334155;
}
```

Start from the template shipped with the theme — `packages/theme/src/css/themes/custom-scheme.template.css` — which has the full shape above with a few more tokens filled in.

Make sure your scheme defines `--color-background` and `--color-primary` in each block: the asset generator reads those two from this file for the theme-color meta tag and the PWA manifest.

## Stable selectors

These classes are part of the theme's styling contract — custom CSS can target them safely. Docusaurus classes (`.navbar*`, `.theme-doc-*`, `.markdown`, `.footer*`, `.pagination-nav*`) no longer exist, and neither do the old `.porto-navbar*`, `.porto-sidebar__*`, `.porto-footer*`, `.porto-search*`, `.porto-pagination*`, `.porto-breadcrumbs*`, `.porto-empty-state*`, `.porto-doc-card`, or `.porto-doc-footer` classes — those components are styled with Tailwind utilities now.

| Selector                                                                          | Element                                                                                                                                                  |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.porto-doc-layout`, `.porto-doc-sidebar`, `.porto-doc-sidebar__expand`           | Doc page layout row, sidebar column, collapse-expand button (the layout also gets `.porto-doc-layout--sidebar-collapsed` while the sidebar is collapsed) |
| `.porto-markdown`                                                                 | Wrapper around rendered MDX content                                                                                                                      |
| `.porto-toc__link--active`                                                        | Active table-of-contents link                                                                                                                            |
| `.portosaur-generated-index`                                                      | Generated index pages                                                                                                                                    |
| `.admonition`, `.admonition-<type>`, `.admonition-heading`, `.admonition-content` | Callouts (`note`, `tip`, `info`, `success`, `warning`, `caution`, `danger`)                                                                              |
| `.code-block-error-line`, `.code-block-success-line`                              | Magic-comment code line highlights                                                                                                                       |
| `.porto-btn`                                                                      | `<Btn>` component (unstyled hook — style it in `custom_css`)                                                                                             |
| `.porto-details`                                                                  | `<Details>` component (unstyled hook — style it in `custom_css`)                                                                                         |
| `.sidebar-item-hidden`                                                            | Hidden sidebar item (root index)                                                                                                                         |
| `.center`, `.hide-this`                                                           | Utility classes                                                                                                                                          |

The `--ifm-*` (Docusaurus) and `--porto-*` (Portosaur 0.x) token names no
longer exist in this theme. The current token names are listed in the
[Tokens](#tokens) section above.
